# 交付格式

## 文件与版式

默认交付 UTF-8 Markdown 正文，文章标题不写入文件，在回复中单独给出。用户指定格式或位置时照办；否则保存在本 skill 的 `成稿/`，用标题作文件名并替换路径非法字符。没有要求覆盖旧稿时，使用新文件名。

自然段之间空一行，一般一至三句一段。关键数字或简短引语可单独成段，不机械地一句一行。

小标题单独一行加粗，正文通常不加粗。分档小标题可以是“金额：这一档的处境”，也可以是简短陈述，不必每档都挂一句金句。编号按递进或并列需要选择，一篇保持一致。档数较多且确有层次时再分组，不硬造意象组名。

账目可以一项一行，让读者容易复算。默认不用表格、引用块、代码块、分隔线和 emoji，不写署名。原文中的“PART 02”、重复抽出的金句、便签和装饰字样属于原版式痕迹，不自动搬进正文。

## 篇幅与计数

默认正文 1100—1500 字，用户另定篇幅时以用户要求为准。这个区间是默认交付约定，不声称四篇原文都落在其中。

计数包含正文小标题、标点、数字和英文字母，每个可见字符计 1，不计空白、文章标题和编辑说明。

`scripts/count_body.py` 只统计纯文本，**不会自动剥离 Markdown**。计数前把正文中的 Markdown 格式标记去掉，将可见正文写入临时 UTF-8 文本，或通过标准输入传入。正文内容和小标题文字保留。

从 skill 目录执行：

```bash
python scripts/count_body.py <正文纯文本文件> --min-length 1100 --max-length 1500
```

修改正文后重新计数。超长先删重复解释、无关场景和重复举例；过短先检查缺了什么过程、条件或代价，不靠增加感悟句凑字数。不必优先保住金句。

## 交付前

检查文件存在、编码正确、标题没有混入正文；金额口径、算法和分档一致；没有假托真实经历或未经证实的统计。按本篇写法检查材料是否够用，不要求白描文出现人物，也不要求算账文一定分档。

最后回复给标题和文件链接。存在虚构素材、计算假设或与用户要求的偏离时，用简短说明交代；不附整套写作流程和自评。
