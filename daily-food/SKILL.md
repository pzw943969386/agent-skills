# 家常晚餐文章写作

用户把今晚做的几道菜和步骤给我，我写成一篇成稿。文章讲菜、讲做法、讲火候里的关键，不讲家里。

## 定位与默认约定

- **一篇文章＝一顿饭的几道菜。**用户会给菜名和步骤，可能很详细，也可能只有几句。缺的部分按「写作前」处理，不要求用户补全。
- **每道菜 100—200 字**，这是核心篇幅口径。另加开篇 60—120 字、收尾 40—80 字。整篇字数按菜数算：

  | 菜数 | 正文大致区间 |
  | :--- | :--- |
  | 2 道 | 300—600 字 |
  | 3 道 | 400—800 字 |
  | 4 道 | 500—1000 字 |

  用户指定别的篇幅时以用户要求为准。
- **自称用“我”，不带称谓。**可以写“我今天做的是”“我的做法是”“这一步我一般会”。不出现“星妈”“XX 妈”这类人设名。
- **文章里不出现家里的人，也不出现家庭场景。**这条是硬约束，比篇幅重要。

## 不出现家里人（硬约束）

例文里那种“家有上学娃”“我家老爷子”“俩娃吃到撑”，一篇都不能有。禁止清单：

- **称谓**：家人、孩子、娃、俩娃、老公、老婆、老人、爸妈、公婆、一家人、全家、舅妈、姑姑等亲属称呼。
- **场景**：给谁做、谁爱吃、谁抢着吃、端上桌就光盘、留一份给谁。
- **变相暗示**：不点名，但让读者看出还有别人在场——“这道菜一上桌就没了”“连不爱吃青菜的人也夹了两筷子”“一锅不够分”。
- **用户步骤里带出来的家庭信息**：用户说“孩子爱吃辣所以我放得少”，写成“辣椒可以按口味增减”，把家庭信息剥掉只留做法。
- “我家”也回避，用“我”。

图片、配文、食材用量说明里同样适用。

## 写作前

1. **用户给了菜名和步骤就直接写**，不再问要几道菜、什么风格、给谁看。菜名不全时按步骤推断，推断不出就用“这道菜”暂代并在交付时说明。
2. **步骤简略时补通用烹饪常识，不编具体数。**可以补“为什么这么做”的解释（“先煸出油再下菜，菜才不出水”“面糊静置一会儿更细腻”）；**不能编用量、火候时间、温度、功率、品牌、师傅来历**。用户没给“炒三分钟”，就不写“三分钟”；用户没说“生抽两勺”，就不写“两勺”。需要读者自己拿捏时，写“按口味调”“看着差不多就行”。
3. **用户步骤里有明显问题时**（食品安全、顺序会导致失败、单位明显不对），照常写，但在正文外单独提一句，让用户决定改不改。不擅自替用户改做法。
4. 出稿前读 [例文拆解](references/例文拆解.md)（写法和语感）和 [交付格式](references/交付格式.md)（版式与字数）。

## 标题

用户给主题就直接拟一个，不让用户先选。例文的标题靠“孩子抢着吃”“一周 8 次吃不够”这类钩子，本篇不出现家里的人，钩子要换成菜本身的卖点。

可用公式：

```text
{时令}这{N}道菜，{整体路数}，{最省事/最下饭的那道}
我常做的{N}道家常菜，{共同卖点}，{口感}
{N}道菜一顿饭，{难度}，{其中最值得学的一处}
{某个食材}买回来别只会{常见做法}，{换的做法}，{口感}
```

示例（结构示意，具体内容随菜定）：

- 入秋这四道菜，有荤有素，最省事的一道十分钟上桌
- 豆腐买回来别只会红烧，这样煎一下，外焦里嫩还不出水
- 三菜一汤的家常搭配，火候都在这几个点上

标题里的每一样都要正文撑得住：说了“十分钟”正文就得有十分钟的说法，说了“三道菜”就真写三道。**不出现家人**（“给孩子做”“全家都爱吃”“一端上桌就光盘”），不编配方来历，不编用量和时间。

## 正文骨架

### 开篇 60—120 字

例文的开篇靠节日和一家人的场面撑着，这篇没有。换成下面任一种由头，一句话破题即可：

- **时令**：入秋以后萝卜开始甜了、连着下了几天雨，菜市场多了什么。
- **食材本身**：一块豆腐买回来，最怕的就是下锅就碎。
- **做法难点**：这道菜翻车的点不在调味，在火候。
- **口味诉求**：想吃点清爽的，又不想太素。
- **常见误区**：很多人炒这道菜，第一步就做错了。

由头之后接一句这顿饭的整体感觉（几道菜、什么路数），然后进正文。

### 每道菜 100—200 字

固定三段式，不写小标题以外的层级：

```text
{菜名}                        ← 小标题

食材：{一行列完，约 20—40 字}

1、{动作 + 为什么}
2、{动作 + 为什么}
3、{动作 + 为什么}
```

- **菜名就是小标题**，用菜本身的名字（“香菇滑鸡”），不加“超好吃”“必学”这类前缀。
- **食材一行列完**，用顿号或逗号分隔，不换行、不分类、不写用量（除非用户给了用量）。
- **步骤 2—4 步**，每步必须有“为什么”。这是例文最值得学的地方：

  | 只有动作（不要） | 动作 + 为什么（要） |
  | :--- | :--- |
  | 葱姜水分三次加入，搅拌 | 葱姜水分三次加，每加一次都搅到吸收再加下一次，一次倒完肉馅就散了 |
  | 加点食用油拌匀 | 切好先拌一圈油，把水分锁住，后面加盐就不容易出水 |
  | 大蒜炒香 | 蒜末先下锅炒到微黄，香味才出得来，炒白了只有生蒜味 |

- 步骤多的时候合并同类动作，**不为凑格式拆成六步**。一步讲不清的，宁可写长一点也不拆。
- **重点靠句子本身说清楚。**该点名的地方直接写“关键在这一步”“很多人栽在这里”“火候差一点，味道差一截”，不用加粗、颜色去喊。全篇唯一的加粗是菜名。

### 收尾 40—80 字

例文收在“给家人做上一盘”。这篇收在菜本身或读者身上：

- 落到菜：口感复述一句，加一个实用场景（凉了也不腥、第二天带饭也行、剩下的可以怎么处理）。
- 落到位：这一桌菜的关键就那么几处。
- 落到读者：想试的话，先从最容易的那道开始。

不写“一定要试试”“记得收藏”这类空号召。要号召就具体：“第一次做，先把茄子煎透，剩下的都好办。”

## 语言规矩

学例文那股热气，只把人去掉。

- **短句为主，逗号串联**，节奏快一点。段落短，一菜一段落。
- **口感词具体**：外焦里嫩、鲜香入味、清爽不腻、咸香适口、汁水收得住。不堆“巨好吃”“绝了”这类空词。
- **技巧句要点名**：“关键在这一步”“很多人栽在这里”“火候差一点，味道差一截”。
- **口语但不轻浮**：可以用“其实”“就是”“说白了”，不用“姐妹们”“家人们”“宝子”。
- 感叹号少量用，一篇两三处。例文里感叹号极多，那是它们的风格，不必照搬。
- 口味、用量、火候按用户给的写；用户没给就说“按口味调”“看着差不多”，不给假数字。

## 事实边界

- **不编配方来历。**“饺子馆 30 年师傅的配方”“跟老师傅学的”属于背书，用户没提供就不写。
- **不编用量、时间、温度。**这是这类文章最容易出的问题——多写一个“三分钟”，读者照做失败，文章就废了。
- **不编营养和健康功效。**不做“补钙”“养胃”“降三高”这类断言。这类内容属于健康科普，改用 `yangsheng` skill，并按其核查要求办。
- **通用烹饪常识要站得住。**“锁住水分”“激出香味”“大火收汁”可以用；讲不出道理的玄学说辞不用（“这样能去寒气”）。
- 食材替换、剩菜处理可以写，但要说清这是建议不是必须，不保证结果一样。

## 交付与计数

- **默认交付一个 `.md` 文件**，正文用 Markdown 写。文章标题不写进文件——公众号编辑器里另有标题输入框，标题在回复里给。版式见 [交付格式](references/交付格式.md)。
- **字数口径：**Markdown 标记剥掉后的可见字符数，含标点、数字和英文字母，每个字符计 1；不计空格、换行等空白。`**` 这类标记不计入。文章标题、署名和编辑说明不计入。
- 交稿前把正文存成 UTF-8 纯文本（不含标题、署名和编辑说明），按菜数传区间再运行：

  ```bash
  python scripts/count_body.py <正文纯文本文件> --min-length 400 --max-length 800
  ```

  区间按上表算（2 道 300—600、3 道 400—800、4 道 500—1000）。调整正文后重新计数。**一道菜明显超出 200 字就压回区间**，先删重复的口感形容，不删“为什么”那一句。
- 交付时给：标题（一句）+ md 文件路径。核查发现的问题、被剥掉的家庭信息、需要用户拍板的地方，用一两句话单独说明，不铺成章节。

## 交付前检查

- 标题里的每样东西正文都撑得住，标题里也没有家人和编的数字。
- 通篇搜一遍“孩子、娃、家人、全家、老公、老婆、老人、家里”，**一处都不能有**；也检查变相暗示有没有漏网。
- 每道菜在 100—200 字之间，步骤都有“为什么”。
- 用量、时间、温度、配方来历都是用户给的，没有自己加的数字。
- 口感词没有重复堆叠，感叹号不超过两三处。
- 收尾没有空号召。
- Markdown 按 [交付格式](references/交付格式.md) 第三节的自检清单过一遍（重点是全篇只有菜名是加粗的、段与段之间都有空行）。
