# API 检测与复测

用户已要求写完文章调用朱雀文本检测，并对 AI 或疑似 AI 段落继续修改。本流程适用于本 skill 交付的文章正文，不自动提交用户的例文、其他文件或无关材料。

## 调用

接口：`https://ai-gateway.edgeone.link/v1/providers/zhuque-text/classify`，POST JSON，正文为 `text`，默认 `is_merge: false`。Authorization 使用 Bearer 密钥。

运行 `scripts/check_ai.py <文章路径> --report <临时报告路径>`。脚本从当前进程的 `ZHUQUE_API_KEY` 环境变量读取密钥。密钥不得写进 skill、脚本、文章、报告、Git 或命令日志；通过可用的安全凭据传递方式注入。没有可用凭据时询问用户如何提供，不凭空沿用不存在的环境变量，不声称已检测。

文章为 UTF-8；脚本移除加粗与 Markdown 标题标记，发送实际可见正文。响应按 UTF-8 解码。报告含提交文本指纹、原始响应与段落，不含凭据；保存到临时目录或用户指定的非公开位置，不混入公众号正文。

## 判断与修改

- `status` 必须为 `success`；失败、超时、字段缺失或额度不足均不算通过。报告错误并停止本次循环，避免自动重试产生未知重复扣费。
- `labels_ratio['1']` 为 AI 占比，`['2']` 为疑似 AI 占比。任一大于零，检查 `segment_labels` 中对应的原文，修改实际存在的机械重复、空泛解释、模板推进和生硬表达后复测。
- 初测后默认最多三轮修改及复测，总计至多四次调用。用户明确指定其他上限时优先遵守。提前达到两项占比都为零即结束；达到上限仍命中则如实交付结果，不自动扩大次数。
- 命中段落优先往例文口吻上改：把碎句并成完整句子，补上“并不是……而是……”“但是”“之后”等连接，把文艺比喻和留白改成大白话和一句直给的判断，把概括改成具体的账和事。对照 [语感样本](语感样本.md) 改。
- 不靠错字、隐藏字符、乱码或删除必要事实追分。保留用户立场、真实素材、标题风格与篇幅。
- 最终交付的正文必须与所报告的检测版本一致；如选择较早版本，就报告那个版本的记录。检测之后如再改正文，需要在预算内重测，或明确说明该新版本未复测。

## 报告

简短给出初测与最终 `labels_ratio`、实际修改轮数、剩余命中。置信度是检测器返回的指标，不是作者身份的概率或“原创率”。按返回字段统计 Makers 用量；无字段不猜测费用。不能因为置信度稍降就宣称通过。

检测只提供编辑参考，不能证明人工创作。该流程补充人工阅读，不取代例文学习与事实检查。
