# 交付格式

用户指定篇幅、格式、目录或标题时优先按要求。以下为默认约定。

## 正文与文件

- 保存 UTF-8 `.md` 到 skill 的 `成稿/`，不存在则创建。用标题命名并去掉路径非法字符；非改稿任务遇到同名文件时另取可辨认的名称。
- 文章标题在回复里给，正文文件不重复写，也不混入素材说明、写作分析和署名。
- 自然段间空一行。一段一到三句，关键的判断可以单独成段；不要一行一个碎句。
- 结构照 SKILL.md 的骨架：叙事篇不设小标题或只用“一二三四”；分档篇用档位做小标题，如“第七级：3000元”。
- 结尾可以加一句评论区提问，多数题目都适合加。
- 正文通常不额外加粗。默认不用表格、代码块、引用块、分隔线、emoji；账单需要展开时按项目分行，显示清楚即可。
- 原文的“PART”、便签、重复摘句等按页面装饰处理，不自动复制；用户要求复刻排版时另行处理。

## 篇幅与计数

正文默认1100—1500字，是交付约定，不是对例文字数的统计结论。包括正文小标题、标点、数字与英文字符，不计空白、文章总标题、来源及编辑说明。

`scripts/count_body.py` 只统计纯文本，不会去除 Markdown。将最终正文的加粗等标记剥掉，保留小标题文字，写入临时 UTF-8 文本。从 skill 目录执行：

```bash
python scripts/count_body.py <正文纯文本文件> --min-length 1100 --max-length 1500
```

用户另定长度时改参数。正文调整后重新提取、计数，不把临时计数稿当成品交付。

超长先删重复说明和多余人物；偏短先补账的后果或再加一个对照人物，不要靠加建议凑字数。

## 交稿

确认文件存在、编码正常、标题承诺兑现，人物关系和数字口径一致。自行拟定的文章总标题须按 SKILL.md 的标题规则连贯写成一句或一个完整短语，不用分隔标点、空格、换行或副标题制造断句；检查时也要读一遍，避免只删逗号却留下两个硬拼的分句。正文里不加来源注释和来源段，跟例文一样；用到的公开数据，来源写在回复里。

回复给标题与文件链接。用一句话说明人物和经历是虚构的典型情况，以及哪些数据待核实。多主题分别给链接，不自行合并。无需附结构分析或评价自己“很有共鸣”。
