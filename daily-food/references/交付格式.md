# 交付格式

**默认交付一个 `.md` 文件**，正文用 Markdown 写。文章标题不写进文件——公众号编辑器里另有标题输入框，标题在回复里给。

## 一、正文版式

```markdown
{开篇段落}

{开篇第二段，可省}

**{菜名一}**

食材：{一行列完}

1、{动作 + 为什么}

2、{动作 + 为什么}

**{菜名二}**

食材：……

1、……

{收尾段落}
```

要点：

- **菜名单独一行，用 `**加粗**`。**这是全篇唯一的加粗，它承担小标题的作用。不用 `##` 标题层级，也不加 ❤️ 这类装饰符号。
- **食材一行列完**，以“食材：”开头，用顿号分隔。
- **步骤编号手写**（`1、2、3、`），不用 Markdown 的有序列表 `1. `。手写编号粘到任何编辑器里都不会被重排。
- **每个自然段之间空一行，步骤之间也空行。**少了空行，Markdown 会把连续几行并成一段。
- **正文里没有别的加粗、下划线或颜色标记。**重点靠句子本身说清楚：该点名的地方直接写“关键在这一步”“很多人栽在这里”，不靠字体加粗去喊。
- 不用引用块、代码块、分隔线、表格。这些在公众号编辑器里要么丢样式，要么显得像技术文档。
- 不用 emoji 做分隔（例文里用来分段的 ❤️ 和空行，这里省掉）。

## 二、字数

按 `scripts/count_body.py` 口径：**Markdown 标记剥掉后的可见字符数**，含标点、数字和英文字母，每个字符计 1；不计空格、换行等空白。`**` 这类标记不计入；文章标题、署名和编辑说明不计入。

交付前把正文存成 UTF-8 纯文本（不含标题、署名和编辑说明），按菜数传区间：

```bash
python scripts/count_body.py <正文纯文本文件> --min-length 400 --max-length 800
```

| 菜数 | 正文区间 |
| :--- | :--- |
| 2 道 | 300—600 字 |
| 3 道 | 400—800 字 |
| 4 道 | 500—1000 字 |

**一道菜明显超出 200 字就压回区间**，先删重复的口感形容，不删“为什么”那一句。

## 三、交付前自检

- 通篇搜一遍“孩子、娃、家人、全家、老公、老婆、老人、家里”，**一处都不能有**；也检查变相暗示（“一上桌就没了”“连不爱吃青菜的也夹了两筷子”）有没有漏网。
- 每道菜在 100—200 字之间，步骤都有“为什么”。
- 用量、时间、温度、配方来历都来自用户，没有自己编的数字。
- **全篇只有菜名是加粗的**，正文里没有别的 `**`。
- 段与段之间都有空行，步骤之间也有空行。
- 菜名不带“超好吃”“零失败”这类前缀。
- 收尾没有空号召。
