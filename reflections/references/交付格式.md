# 交付格式

**默认交付一个 `.md` 文件**，正文用 Markdown 写。文章标题不写进文件——公众号编辑器里另有标题输入框，标题在回复里给。

## 一、正文版式

### 分档盘点型

```markdown
{开篇段落，一两句一段}

{开篇第二段}

**{档名一}：{判断句}**

{人物和细节}

{引语}

{判断}

**{档名二}：{判断句}**

……

{收尾段落}
```

要点：

- **档名用“金额或状态：核心洞察”的格式，单独一行加粗**，如“3000 元以下：贫穷的本质是没有选择”“点头之交，200 元：不是情分，是社交保险费”。洞察就是这档最狠的那句判断，读了标题就知道这档讲什么。这是全篇唯一的加粗。
- 档数多时分组，组名也单独一行加粗，放在该组第一档之前。**组名要有意象、有层次**（“起点与台阶”“够花与不够花”“账外”），不写成提纲（“四种关系”“两种例外”这种说明文标签）。**分档逻辑要统一**（全按金额或全按关系），混不进去的归到例外组。
- **引语独立成段**，用引号，不另起引用块。
- 编号（“一、二、三”）可用可不用：分档逻辑是递进的（从低到高）就不编号，靠档名里的数字区间走；是并列的就编号。一篇统一。

### 一笔账型

```markdown
{开篇段落：反常识结论 + 学费}

{摊账段落}

{各项支出逐项列出，一项一行}

{合计 + 一句判断}

{方法段落}

{分层建议，一档一段}

{收尾段落}
```

要点：

- **摊账时各项支出一项一行**，便于读者对着数（“月供 3800 元 / 车位 600 元 / 汽油费 1500 元……”）。不用表格——表格在公众号编辑器里容易丢样式。
- 小标题用判断句（“月供之外，还有一条很长的尾巴”“算全年，除十二”），不用“第一部分”“原因有二”这类标签。

### 两种骨架通用

- **每个自然段之间空一行。**段落极短是这类文章的呼吸，一两句一段，空行不能省。
- **全篇只有小标题是加粗的**，正文里没有别的 `**`、下划线或颜色。重点靠句子本身说清楚。
- 不用引用块、代码块、分隔线、表格、emoji。
- 不写署名。

## 二、字数

按 `scripts/count_body.py` 口径：**Markdown 标记剥掉后的可见字符数**，含标点、数字和英文字母，每个字符计 1；不计空格、换行等空白。标题、编辑说明不计入。

交付前把正文存成 UTF-8 纯文本（不含标题和编辑说明），运行：

```bash
python scripts/count_body.py <正文纯文本文件> --min-length 1100 --max-length 1500
```

默认区间 1100—1500 字，三篇例文都落在这里。用户另定篇幅时传对应区间。超出区间先并档或删重复的例子，不删每档的判断句。

## 三、交付前自检

- 通读一遍，没有语病，没有例文那种改写痕迹（“六五千块钱”“三万个个人”）。
- 全篇的账验算过：每档的数、合计、算法示例都对得上。
- 每档四件套齐全（人物、细节、引语、判断），没有空有判断的档。
- 全篇只有小标题加粗，段与段之间都有空行。
- 感叹号不超过一处。
- 每档档眼是硬断言，不是对仗工整的修辞句；“我”在场但主角是群像，至少一两档写的是别人。
- 开头有冲突场景，不是日记式自述；收尾最后两句贴本篇主题，没套例文模板。
- 没有“据统计”“专家说”类无出处背书，没有理财建议。
- 收尾落在反焦虑上。
